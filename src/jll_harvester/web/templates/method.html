Ziel: Gewerbegrundstücks-Transaktionen und Big-Box-Industrie-/Logistikvorhaben aus dem öffentlichen Research- & Transaktions-Newsroom von JLL Deutschland erkennen, verorten und nachvollziehbar in iris_staging.signal_ingest laden.

Quelle & Zugriff

  • Der Brief nennt {{ settings.brief_endpoint }}. Diese URL antwortet heute mit 301 auf jll.com/de-de/insights/market-dynamics — geprüft bei jedem Lauf und im Run-Ledger protokolliert.
  • Die Listenansicht wird clientseitig gerendert; „Mehr laden“ paginiert per Query-String. robots.txt verbietet genau das (Disallow: /*?). Zugriffsbeschränkungen werden nicht umgangen.
  • Rechtmäßige Alternative: die in robots.txt verlinkte Sitemap {{ settings.sitemap_url }}. Sie listet alle Pressemitteilungen (/de-de/newsroom/…) und Research-Seiten mit <lastmod> — vollständige Enumeration ohne Pagination und inkrementelle Läufe.
  • Höflicher Crawler: eigener User-Agent, ≥ {{ settings.request_delay_seconds }} s Abstand, RFC-9309-konforme robots-Auswertung (inkl. Wildcards), Retries mit Backoff und Retry-After.

Pipeline

discover → inkrementell filtern → fetch → parse → klassifizieren → verorten → validieren → idempotent laden. Jedes Dokument läuft in einer eigenen Transaktion; Fehler werden als ingest_issue erfasst und brechen den Lauf nicht ab.

  • Parsing: Titel und Veröffentlichungsdatum aus JSON-LD (NewsArticle.datePublished), gegengeprüft gegen die Dateline („MÖNCHENGLADBACH, 16. Juli 2026 –“). Abweichungen werden markiert, nie stillschweigend übernommen.
  • Taxonomie: JLLs eigene Tags (news/transactions, property-types/industrial-and-logistics, …) aus <meta name="ch.tagcloud">.

Klassifikation

Transparente, deutschsprachige Regeln statt Black-Box — jede Entscheidung speichert ausgelöste Regeln, Scores und Belegstellen.

Gewerbegrundstück-Transaktion

  • Ein Grundstück, Areal, Gelände, Brownfield wechselt den Eigentümer (erwirbt, kauft, verkauft, veräußert).
  • Abzug, wenn das Objekt ein Bestandsgebäude ist („Bürogebäude“, „Fachmarktzentrum“) oder die Nutzung rein wohnwirtschaftlich ist.

Big-Box Industrie & Logistik

  • Industrie-/Logistik-Bezug (Taxonomie oder Begriffe wie Logistikzentrum, Produktion, Light Industrial, Rechenzentrum) und
  • Projektentwicklung (Neubau, Baustart, spekulativ, Revitalisierung …) oder Big-Box-Größe ≥ {{ fmt_number(settings.big_box_min_sqm, locale) }} m².

Ausgeschlossen mit Begründung: Personalmeldungen, aggregierte Marktberichte, Büro-/Einzelhandels-/Wohn-Deals, Signale außerhalb Deutschlands, Konfidenz < {{ settings.min_classification_confidence }}.

Verortung (EPSG:25832)

  • Ortsangaben werden kontextbasiert erkannt: Adresse („am Regioparkring 4“), Stadtteil („Bonn-Auerberg“, „im Bonner Stadtteil …“), Präposition („in Mönchengladbach“), Demonym („Kölner …“), Dateline.
  • Geocoding so genau wie möglich: Nominatim (OSM, Nutzungsrichtlinie eingehalten, Cache) → Offline-Gazetteer GeoNames (Gemeinde/Stadtteil).
  • Validierung: endlich, innerhalb Deutschlands, ≤ 30 km von der erwarteten Gemeinde, innerhalb des EPSG:25832-Gültigkeitsbereichs. Sonst invalid — der Punkt wird verworfen, der Grund gespeichert.
  • Mehrdeutig (z. B. Portfolio in mehreren Städten) oder nur Region („in Oberbayern“) → kein geratener Punkt, Kandidaten werden dokumentiert.

Staging & Idempotenz

  • Natürlicher Schlüssel (source_system, source_record_id) mit UNIQUE-Constraint — Wiederholungsläufe erzeugen keine Duplikate.
  • content_hash über die fachlichen Felder: unverändert → nur last_seen_at; geändert → Update mit record_version + 1; nicht mehr relevant → retracted_at statt Löschung.
  • DB-Constraints erzwingen: Punkt ⇔ resolved, gültige Geometrie innerhalb Deutschlands, SRID 25832.

Grenzen

  • Regelbasierte Klassifikation ist auf die Sprache von JLL-Pressemitteilungen abgestimmt; Grenzfälle erhalten niedrige Konfidenz und Qualitäts-Flags.
  • Adressgenaue Punkte nur, wenn die Quelle eine Adresse nennt; sonst Stadtteil- oder Gemeindezentroid (als Flag sichtbar).
  • Die Dateline nennt oft das JLL-Büro, nicht den Standort — sie wird daher nur nachrangig genutzt und markiert.

Goal: detect, locate and traceably load commercial land disposals and big-box industrial/logistics development signals from JLL Germany's public research & transactions newsroom into iris_staging.signal_ingest.

Source & access

  • The brief names {{ settings.brief_endpoint }}; it now returns 301 to jll.com/de-de/insights/market-dynamics — verified on every run and logged in the run ledger.
  • The listing is client-side rendered and paginates via query strings, which robots.txt forbids (Disallow: /*?). Access restrictions are not bypassed.
  • Lawful alternative: the robots-advertised sitemap {{ settings.sitemap_url }} with <lastmod> — complete enumeration without pagination plus incremental runs.
  • Polite crawler: identifying UA, ≥ {{ settings.request_delay_seconds }} s spacing, RFC 9309 robots evaluation (wildcards), retries with backoff and Retry-After.

Pipeline

discover → incremental filter → fetch → parse → classify → locate → validate → idempotent load; one transaction per document, failures become ingest_issue rows and never abort the run. Publication dates come from JSON-LD and are cross-checked against the dateline.

Classification

Transparent German-language rules; every decision stores rules fired, scores and evidence snippets. Land disposal = a plot/site/brownfield changes hands (penalised when the object is a standing building or residential). Big-box = industrial/logistics context and development cues or ≥ {{ fmt_number(settings.big_box_min_sqm, locale) }} m².

Location (EPSG:25832)

Context-aware place extraction (address, district, preposition, demonym, dateline) → Nominatim (policy-compliant, cached) → offline GeoNames gazetteer. Points must be finite, in Germany, ≤ 30 km from the expected municipality and inside the EPSG:25832 area of use, otherwise they are rejected as invalid. Multi-site or region-only mentions stay without a point and keep their candidates.

Staging & idempotency

UNIQUE natural key, content hash (unchanged → touch only; changed → record_version + 1; no longer relevant → retracted_at), DB constraints for geometry/status consistency.

Limitations

Rules are tuned to JLL press-release language; address-level points only where the source names an address; datelines often name the issuing JLL office and are therefore used last and flagged.
